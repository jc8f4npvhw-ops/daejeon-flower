# 기념일 등록 경험과 주변 약도

2026-10-18 고객 페이지 수정.

- 가입과 결제 입력 과정에서 기념일을 필수로 요구하지 않는다.
- 결제 서버가 PAID를 확인한 꽃다발·꽃바구니·센터피스 주문에 선택형 안내를 표시한다. 근조화환을 비롯한 다른 상품과 실패·대기 상태에는 표시하지 않는다.
- 결제 완료 안내의 등록 버튼은 마이페이지 기념일 메뉴로 연결된다. 로그인 연결 전에는 기존 로그인 준비 화면을 유지한다.
- HTML 미리보기에서는 예시 주문 상세의 ‘주문 완료 후 기념일 안내 보기’로 확인할 수 있다.
- 먼저 알림 예시를 보여주고 날짜 하나를 등록한다. 월·일과 종류를 선택하며 이름·연락처·태어난 연도는 추가로 받지 않는다.
- 이름과 선물 메모는 선택. 입력한 메모는 기념일 카드와 수정 창에서 확인한다.
- 내 생일은 가입 시 입력한 월·일을 불러온 뒤 고객이 확인하여 저장한다. 자동 등록하지 않는다.
- 알림은 기본 해제. 날짜만 저장할 수 있으며 알림과 광고성 혜택 수신을 분리한다. D–3 고정.
- 수령일을 기념일로 자동 전환하지 않는다. 양력 반복, 평년 2월 29일은 2월 28일 기준.
- ‘지금은 괜찮아요’로 넘어갈 수 있다. 이번 화면에서 반복 안내하지 않는다.
- 실제 회원 인증·D1 저장·채널 상태 확인·알림 템플릿 발송은 아직 연결 전. 미리보기 입력은 메모리 상태이며 실제 신청이 아니다.

## 관리자/연동 후속 작업

현재 원격 D1 스키마를 조회한 뒤 기존 기념일 테이블에 맞춰 연결한다. 새 DB·테이블 교체 금지.
필요한 경우 memo 등 부족한 열만 추가 migration으로 반영한다.
회원 본인의 기념일만 조회·수정·삭제하도록 인증과 소유권 검사를 적용한다.
알림 신청/해제 시각, 동의 안내 버전, 채널 상태, 발송 중복 방지를 함께 설계한다.
지난 선물 연결은 실제 주문과 고객이 확인한 관계만 사용한다. 예시 주문을 실데이터로 취급하지 않는다.
쿠폰·할인 금액은 변경하지 않았다. 배송완료 사진 → 리뷰 → 다음 주문 1,000원 쿠폰은 카카오 연결 시 재안내할 별도 흐름이다.

전체 연결 점검 결과와 한 번에 진행할 작업

이번 수정: 아직 운영 배포하지 않았습니다.
1. 관리자 고객 목록/상세가 실제 카카오 회원 테이블의 연락처·생일·계정 연결을 표시합니다.
2. 회원 약관, 주문 동의, 기념일 광고 수신, 채널 친구 본인 확인을 각각 실제 저장 기록으로 표시합니다.
3. 입력한 연락처와 확인된 발송용 연락처를 구분합니다. 입력만 한 번호를 자동으로 검증 처리하거나 기존 비회원 주문과 합치지 않습니다.
4. 알림 설정에 서버 변수/비밀/기념일 템플릿/본인 시험 번호의 준비 여부를 한 화면에 표시합니다. 비밀값은 표시하지 않습니다.
5. 사용자가 Cloudflare에서 이미 변경한 ANNIVERSARY_COUPONS_ENABLED=true를 소스에도 반영하여 다음 Git 배포 때 false로 되돌아가지 않게 합니다.
6. 전화번호 숫자 키패드·자동 하이픈과 한글 연도/월/일 달력을 포함합니다.

병현님이 해야 할 외부 작업 (화면 캡처 반복 불필요):
- 카카오 Developers에서 진행 중인 사업자/개인정보 제공 권한 심사 결과를 확인합니다. 회원의 전화번호 제공 동의가 준비되지 않은 현재, 직접 입력한 번호는 발송용 검증이 완료된 번호가 아닙니다. 관리자 표시 수정이 이 검증을 대신하지 않습니다. 권한 승인 후 기존 회원의 전화번호 확인 갱신 과정도 연결해야 합니다.
- SOLAPI에서 배송완료용과 별개인 기념일 전용 브랜드 메시지 템플릿을 준비합니다. 현재 코드가 쓰는 변수명은 #{기념일명}, #{기념일날짜}입니다. 실제 승인된 템플릿과 API 사용 가능 상태를 확인해야 합니다. ID를 임의로 만들거나 배송완료 템플릿 ID를 복사하지 않습니다.
- 템플릿이 준비되면 Cloudflare 설정을 한 번에 합니다: SOLAPI_ANNIVERSARY_TEMPLATE_ID=실제 템플릿 ID, ANNIVERSARY_SENDING_ENABLED=true, ANNIVERSARY_LIVE_SEND_ENABLED=false 유지, KAKAO_TEST_PHONE=본인 휴대전화번호(비밀). 기존 SOLAPI 키·시크릿·채널·PUBLIC_ORIGIN·SESSION_SECRET은 유지합니다.
- 서버 준비만으로 메시지는 발송되지 않습니다. 홈페이지 관리자 스위치와 고객별 알림 신청·광고 수신 동의·채널 친구 본인 확인·발송용 연락처가 모두 필요합니다. 본인 시험을 마치기 전 고객 전체 발송은 켜지 않습니다. 쿠폰 발급/사용 검증과 실제 메시지 수신 검증은 별개입니다.

고객 단계: 생일/기념일 저장, 전화번호 입력, 카카오 로그인은 서로 다른 상태입니다. 채널 친구 표시는 현재 고객 본인의 확인 기록이며 카카오 API 실시간 조회 결과라고 표시하지 않습니다.
쿠폰은 고객 본인 계정에 연결되지만 사용 시 주문자 연락처 조건도 검증하므로 연락처 확인이 선행되어야 합니다.
연결해제 웹훅은 요청에 따라 보류하고 포함하지 않았습니다. 결제·배송완료 발송·고객 전체 발송을 이번 수정으로 켜지 않습니다.

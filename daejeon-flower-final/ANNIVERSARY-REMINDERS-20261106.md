# 통합 대기본: 뒤로가기 + 기념일 D-3 자동 안내

지금은 배포/실제 메시지 발송 전입니다. 추가 요청을 같은 통합본에 계속 반영합니다.

## 이번에 구현한 내용
- 뒤로가기 1회 메인 복귀/스크롤 복원과 기존 사진 경량화 모두 포함.
- 고객 기념일의 실제 DB 저장·수정·삭제, 매년 D-3 신청, 광고 수신동의와 채널 친구 자기확인 분리.
- 관리자 > 알림: 오늘/향후 7일/전체(페이지당 100개), 자동 ON/OFF, 최근 50개 결과.
- 기존 고객 검색, 고객 정보 수집 안내·동의 확인 후 신규 고객 등록, 고객별 1회용 관리 링크 발급. 등록만으로 광고 수신동의를 만들지 않음.
- 브라우저를 닫아도 기존 Cloudflare 5분 주기 서버 스케줄러가 실행. 한국시간 오전 10시부터 18시 전까지 당일 대상을 확인합니다. 10시 실행이 지연되면 같은 날 다음 주기에 확인합니다. 전날 놓친 메시지를 다음날 늦게 보내지는 않습니다.
- 같은 기념일 기록/해당 연도에 한 번 요청. 병렬 실행도 원자적 상태 선점으로 중복을 방지합니다.
- 발송 직전에 날짜·삭제·알림 신청·광고 수신동의·연락처·전체 스위치를 재확인합니다. 이미 업체에 요청한 메시지는 취소할 수 없을 수 있습니다.
- 업체 접수(ACCEPTED)와 최종 전달(SENT/FAILED) 구분. 모호한 통신 결과(UNKNOWN)는 자동·수동 재전송 버튼 없이 업체 기록 확인 대상으로 남깁니다.
- 입력 날짜는 양력 기준이며 음력 자동 변환은 포함하지 않습니다.
- 2월 29일은 평년에 2월 28일로 안내. 연말을 넘기는 D-3 계산 포함.
- SMS 자동 대체발송 없음. 쿠폰 자동발급은 후속 ANNIVERSARY-COUPONS-20261107.md를 따릅니다. 배송완료 템플릿/발송 스위치는 변경하지 않음.

## 카카오 로그인 연결 전의 고객 진입
기존 고객 마이페이지는 미리보기이며 카카오 OAuth/회원 인증이 아직 연결되지 않았습니다. 이를 실제 로그인으로 가장하지 않습니다.
현재 구현한 등록은 매장에서 본인 확인 후 발급한 전용 링크로 합니다. 링크는 7일간 1회 사용, 기기 관리 권한은 30일입니다. 새 링크를 발급하면 기존 링크/해당 고객의 기존 기기 권한을 해제합니다.
링크 원문은 DB에 저장하지 않고 해시만 저장하며, 최초 접속 후 주소창 조각에서 제거합니다. Secure/HttpOnly/SameSite 쿠키와 CSRF 검증을 사용합니다. 다른 고객의 기념일은 조회/수정할 수 없습니다. 주문 내역·가입 생년월일을 이 관리 권한으로 공개하지 않습니다.
로그인 연동이 완료되면 인증된 회원에게 같은 고객 ID를 연결해야 합니다. 현재 단계에서 전화번호 입력만으로 자동 로그인/기존 고객 연결을 허용하지 않습니다.

## 통합 배포 때 필요한 순서 — 지금 실행하지 않아도 됩니다
1. D1에 migrations/0007_anniversary_reminders.sql만 먼저 적용합니다. 기존 DB를 새로 만들거나 기존 자료를 삭제하지 않습니다. 신규 테이블·색인을 추가하는 재실행 가능한 SQL입니다.
   CLI를 사용할 경우 저장소 루트에서:
   npx wrangler d1 execute daejeon-flower-db --remote --file migrations/0007_anniversary_reminders.sql
   기존 마이그레이션을 수동 실행해온 경우 전체 migrate를 재실행하지 말고 위 신규 파일만 적용합니다.
2. 같은 daejeon-flower-final에 소스를 반영하고 Commit/Push. Cloudflare 빌드 성공 확인.
3. 관리자 > 알림에서 고객 관리 링크 발급 → 고객이 날짜/동의 직접 저장 → 새로고침으로 실제 DB 저장 확인.
4. SOLAPI 브랜드 텍스트 템플릿 준비. 배송완료 알림톡 템플릿과 별개입니다. type/targeting은 공식 템플릿형 예제의 자동 감지 + bms.targeting=I(채널친구)로 제한했습니다.
   필수 변수는 정확히 두 개: #{기념일명}, #{기념일날짜}. 날짜는 YYYY-MM-DD 문자열입니다.
   문구 초안: “(광고) 대전꽃백화점 / #{기념일명}이 3일 앞으로 다가왔어요. / 기념일: #{기념일날짜} / 소중한 날을 미리 준비해보세요.”
   광고 표시·수신거부 등 최종 템플릿 요건은 SOLAPI/카카오의 현재 안내에 맞춰 확정합니다. 초안을 등록한 사실만으로 발송 설정이 완료되지는 않습니다.
5. Cloudflare 변수 SOLAPI_ANNIVERSARY_TEMPLATE_ID에 등록한 브랜드 템플릿 ID 입력. 기존 SOLAPI 키·채널·PUBLIC_ORIGIN·SESSION_SECRET을 재사용합니다. 비밀키를 대화나 관리자 문구칸에 입력하지 않습니다.
6. ANNIVERSARY_SENDING_ENABLED=true, ANNIVERSARY_LIVE_SEND_ENABLED=false 유지, 기존 KAKAO_TEST_PHONE에 본인 번호 설정. KAKAO_SENDING_ENABLED도 true여야 합니다. 관리자 자동 발송 ON은 준비된 환경에서만 가능합니다.
7. 본인 고객 기록으로 3일 후 기념일과 두 수신 설정을 신청하여 10시 이후 실제 접수/수신 확인. 전달 완료/중복 방지/해제 테스트 후에만 ANNIVERSARY_LIVE_SEND_ENABLED=true로 고객 발송 전환합니다. 배송완료의 KAKAO_LIVE_SEND_ENABLED와 분리되어 있습니다.

기본 ZIP의 ANNIVERSARY_SENDING_ENABLED 및 ANNIVERSARY_LIVE_SEND_ENABLED는 false, DB의 enabled도 0입니다. 설정값을 바꾼 후 추후 Git 배포할 때 wrangler.jsonc 기본값이 다시 false를 덮어쓸 수 있으므로 확정 운영값은 배포 설정과 함께 관리해야 합니다.

## 제한과 다음 작업
- 카카오 OAuth 연결, 생년월일 기반 자동가입, 쿠폰 발행은 이번 기능과 별개이며 여전히 미연결입니다.
- 기존 anniversaries 표의 과거 등록을 광고 수신동의로 자동 승격하지 않습니다. 새 등록/동의는 별도 표로 보존합니다.
- 이번 검증에서는 실제 카카오 메시지를 보내지 않았습니다. 운영 D1 SQL 적용, 실제 휴대폰 렌더링, 브랜드 템플릿 준비, 본인번호 수신 확인은 통합 배포 때 필요합니다.

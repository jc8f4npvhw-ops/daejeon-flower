# 결제 완료 후 기념일 등록

이번 변경은 일괄 배포 대기본입니다. 실제 사이트 배포, 실제 결제, 쿠폰 발행 및 메시지 발송은 실행하지 않았습니다.

- 결제 API가 PAID를 확인한 경우에만 결제 완료·주문 확정 화면을 표시합니다.
- 완료 화면 안에서 기념일 이름·양력 날짜를 등록할 수 있습니다. 건너뛰어도 주문에는 영향이 없습니다.
- 쿠폰 기능이 활성화된 경우 다음 기념일의 3일 전 2,000원 발급을 안내합니다. 비활성 상태에서는 쿠폰을 약속하지 않습니다.
- 이미 D-3가 지난 날짜는 다음 해부터 시작합니다. 같은 등록 요청을 다시 보내도 중복 등록되지 않습니다.
- 카카오 알림과 광고 수신은 별도 선택입니다. 쿠폰 발급은 광고 수신동의를 요구하지 않습니다.
- 기존 기념일 관리 페이지를 유지하고 두 화면 모두 친구 확인 체크 아래 노란색 채널 추가 버튼을 표시합니다. 채널 열기가 실제 친구 추가 확인을 뜻하지 않으므로 자동 체크하지 않습니다.
- 채널 주소는 운영 콘텐츠 설정을 사용합니다.

## 배포 시 순서

1. 기존 일괄 수정과 함께 반영합니다. migrations/0007, 0008 적용 여부를 확인한 다음 0009_payment_anniversary_access.sql을 운영 D1에 적용해야 합니다. 기존 데이터는 삭제하지 않습니다.
2. 배포 후 결제 테스트 환경에서 성공·실패·재시도, 기존 고객·새 고객, 모바일 화면을 확인합니다.
3. 쿠폰·알림 운영 스위치는 확인 전 OFF로 유지합니다. 기존 배송사진 알림 설정은 바꾸지 않습니다.

## 고객 접근

검증된 결제 링크를 가진 새 고객에게 기념일 관리용 보안 세션을 발급합니다. 이미 등록된 전화번호라면 임의 입력한 번호로 기존 고객 정보를 가져가지 않도록, 기존 기념일 관리 세션 또는 매장에서 발급한 관리 링크가 필요합니다. 실제 고객 로그인 통합은 별도 작업입니다.

## 검증

전체 자동 테스트 88개, TypeScript 검사, 프로덕션 빌드 통과. 독립 HTML에서 결제 완료 → 등록 열기·건너뛰기·저장, 친구 추가 URL, 기존 고객 화면과 관리자 화면 전환을 확인했습니다. 실제 PG 승인·카카오 발송·브라우저 화면 배치 검증은 배포 전 테스트 대상입니다.

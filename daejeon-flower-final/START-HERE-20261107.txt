개인정보처리방침 별도 패치를 다시 적용할 필요가 없습니다.

1. GitHub Desktop에서 daejeon-flower / cloudflare-latest를 확인하고 Fetch/Pull합니다.
2. 이 ZIP은 다운로드 폴더에서 압축을 풉니다. Repository → Show in Explorer로 저장소를 엽니다.
   압축 안 daejeon-flower-final의 내용물을 저장소의 기존 daejeon-flower-final에 덮어씁니다.
   폴더 안에 같은 이름의 폴더를 하나 더 만들지 마세요. ZIP 자체는 저장소에 넣지 마세요.
   기존 폴더 전체를 삭제하지 마세요.
3. 아직 Commit/Push하지 말고, 저장소 daejeon-flower-final 안 prepare-deploy.cmd를 실행합니다.
   Node.js/npm이 필요합니다. Cloudflare 로그인 창에서 기존 계정으로 로그인합니다.
   기존 주문 DB에 기념일·쿠폰용 테이블과 없는 열만 추가합니다. 고객/주문은 삭제하지 않습니다.
   READY가 나오면 준비가 끝났습니다. STOP 또는 오류가 나오면 Push하지 말고 오류 화면을 공유해주세요.
   다른 안내의 npm run migrate를 함께 실행하지 마세요. 기존 DB는 과거 마이그레이션 이력이 다를 수 있습니다.
4. GitHub Desktop Changes에서 변경 파일을 확인합니다.
   Summary: 기념일·쿠폰·뒤로가기·개인정보처리방침 일괄 반영
   Commit → Push origin을 누릅니다.
5. Cloudflare → Workers 및 Pages → daejeon-flower → 배포에서 성공을 확인합니다.
   기존 빌드/배포 명령, DB/R2 바인딩, 비밀 값은 그대로 유지합니다.

이번에 포함한 코드
- 앞서 적용한 경량화, 사진 전환 개선, 베스트셀러 바로 주문, 식물관리 및 기존 기능 유지
- 베스트셀러/브라우저 뒤로가기 수정 및 스크롤 복원
- 관리자 로그인 유지·아이디 저장, 간결한 기념일 관리 화면
- 매년 기념일 D-3 알림, 2,000원 쿠폰, 서버 검증/중복 방지/사용 이력
- 결제 승인 확인 후 완료·주문 확정 표시 및 선택형 기념일 등록 연결
- 버튼형 기념일 분류, 조건부 날짜/메모, 사귄날 계산 및 카카오 친구 추가 버튼
- 실제 /privacy 페이지와 홈페이지 하단 링크, 담당 주병현 직원 반영
- 기존 DB에 일부만 반영되어 있어도 빠진 열을 추가하는 배포 준비 도구

이번 배포로 활성화하지 않는 항목
- 실제 카드결제: PG 연결/실결제 검증이 별도로 필요합니다.
- 카카오 로그인: 개발자 앱 심사·키·콜백 구현/연결이 남아 있습니다.
  채널 친구 추가만으로 자동 로그인되지 않습니다.
- 기념일 자동 쿠폰/발송: 코드만 포함합니다. 운영 스위치는 OFF로 두었습니다.
  DB 설정과 환경변수 모두 켜야 합니다. 실제 발행/발송 테스트 전 켜지 마세요.
- 100일/200일 계산은 표시 기능입니다. 별도 100일 쿠폰을 발행하지 않습니다.
- 리뷰 1,000원 쿠폰 자동 발행과 부분 환불 기능은 이번 완료 범위가 아닙니다.

# 통합 대기본 — 기념일 쿠폰과 간단한 관리자 화면

아직 배포·운영 설정 변경·실제 발송·실제 결제를 하지 않았습니다. 뒤로가기 수정과 이전 기념일 D-3 알림, 사진 경량화를 모두 포함합니다.

## 기본 쿠폰 조건
- 등록한 양력 기념일마다 매년 2,000원. 기념일 3일 전부터 발급하고 기본 사용기한은 기념일 후 7일까지입니다.
- 관리자는 사용기한을 당일/3/7/14/30일로 변경할 수 있습니다. 변경 후 새로 발급하는 쿠폰부터 적용됩니다.
- 같은 기념일 기록/해당 연도 1장, 같은 고객/동일 날짜도 1장. 같은 날 이름만 다른 기념일을 여러 개 등록해도 중복 발급되지 않습니다.
- 늦게 등록한 경우에도 그 해의 쿠폰 유효기간 안에 있으면 다음 실행에서 발급합니다. 2월 29일은 평년에 2월 28일 기준입니다.
- 광고 수신동의와 쿠폰 발급은 분리됩니다. 날짜 등록만으로 쿠폰을 받을 수 있고 카카오 알림은 별도 신청입니다.
- 주문당 1장, 상품금액에서 2,000원 할인. 배송비 제외, 다른 쿠폰 중복 할인 없음. 상품금액이 2,000원 이상이고 할인 후 결제금액이 양수여야 합니다.
- 이미 발급한 쿠폰은 기념일 삭제 시에도 기존 기한을 유지합니다. 현금으로 교환하지 않습니다.

## 연결된 기능
- 고객 기념일 등록 혜택 안내와 쿠폰함(사용 가능/결제 준비/결제 확인/사용 완료/만료).
- 관리자 첫 화면은 다가오는 기념일과 상태 요약만 표시합니다. 고객 등록 도구·발송 결과·세부 설정을 필요할 때 엽니다. 이번 단순화는 관리자 전체가 아닌 기념일/쿠폰 메뉴에 적용했습니다.
- 기존 Cloudflare 5분 주기 스케줄러에서 한국시간 10시~18시 전 쿠폰 발급 실행. 카카오 발송과 독립적인 서버/관리자 스위치를 사용합니다.
- 고객별 전용 관리 세션으로 본인 쿠폰만 조회. 15분 서명으로 선택권한 검증. 할인액과 고객 ID를 브라우저 입력값 그대로 신뢰하지 않습니다. 주문자 연락처도 등록 연락처와 일치해야 합니다.
- 픽업 주문 및 배송비 확정 후 주문 모두 서버에서 2,000원 차감. 배송비는 보존하고 주문/결제/고객 귀속/할인 내역을 함께 기록합니다.
- 주문 생성과 쿠폰 예약은 DB 한 트랜잭션. SQL 고유 제약/트리거로 이중 사용을 차단합니다. 같은 요청의 재전송은 같은 주문으로 처리합니다.
- 결제 준비 취소 시 미사용 쿠폰 반환 + 이전 결제 링크 무효화. 결제 승인 확인을 시작하면 잠금, 성공하면 사용 완료.
- 통신 결과가 불분명한 결제의 쿠폰을 자동으로 풀지 않습니다. 결제사 내역을 확인해야 하며 확인 없이 재발급/반환하지 않습니다.
- 결제사 전액 취소가 확인된 경우에만 기존 쿠폰을 원래 기한 그대로 반환. 현금 환불은 할인 후 실제 결제액입니다. 원래 기간이 지난 쿠폰은 반환되어도 만료입니다.
- 결제 준비 시점뿐 아니라 결제 확인 시작 시점에도 쿠폰 유효기간을 확인합니다.

## 통합 배포 순서 — 지금 실행할 필요 없음
1. 기존 D1에 신규 SQL 0007·0008을 적용합니다. 기존 DB 재생성/초기화는 하지 않습니다.
   npx wrangler d1 execute daejeon-flower-db --remote --file migrations/0007_anniversary_reminders.sql
   npx wrangler d1 execute daejeon-flower-db --remote --file migrations/0008_anniversary_coupons.sql
   예전 SQL을 수동 적용해 왔다면 전체 migrate 대신 위 신규 파일만 적용합니다.
2. 기존 daejeon-flower-final에 통합본 내용 덮어쓰기 → Commit/Push → 빌드 확인.
3. 관리자 > 알림 > 고객 등록 돕기에서 본인 확인 후 전용 링크 발급. 고객이 날짜/수신 설정을 직접 저장합니다. 카카오 OAuth 로그인은 아직 미연결입니다.
4. 쿠폰 테스트 환경에서 ANNIVERSARY_COUPONS_ENABLED=true 및 관리자 > 알림 > 설정의 쿠폰 스위치 ON. 기본 ZIP의 서버값과 DB값은 모두 OFF입니다.
5. PG 테스트 연결 후 본인 기록으로 발급/픽업 할인/배송 할인/이중 사용 차단/결제 준비 취소/결제 성공/전액 취소 반환을 실제 흐름에서 확인합니다. PAYMENTS_ENABLED는 현재 false이며 PG 계약·키와 정책 확정 없이 실결제용으로 켜지 않습니다.
6. 기념일 카카오 알림은 별도 브랜드 템플릿과 본인 번호 수신 테스트가 필요합니다. 쿠폰을 켜는 것만으로 카카오 메시지가 발송되지 않습니다. 쿠폰 안내를 메시지에 넣으려면 실제 조건과 템플릿 문구를 함께 맞춥니다.

운영 화면의 쿠폰 약속 문구는 서버 쿠폰 기능과 관리자 스위치가 켜져 있을 때 표시됩니다. 확인용 HTML은 혜택을 켠 뒤의 예시이며 실제 발급/결제/발송을 하지 않습니다.

## 검증
타입 검사, Cloudflare/Vinext 빌드, 전체 자동 테스트 84개 통과. 외부 메시지/결제는 모의 응답으로 검사했으며 실제 요청하지 않았습니다. 확인용 HTML의 고객 쿠폰함·등록 화면·관리자 메뉴 전환도 서버 없이 검사했습니다. 운영 D1 적용과 실제 휴대폰/PG/카카오 수신 확인은 통합 배포 때 필요합니다.

# 고객 주문 입력 단계 스크롤 점검 · 2026-10-19

## 원인

공통 SchedulePicker는 날짜 선택 후 시간 목록을 렌더링하지만 그쪽으로 스크롤하지 않았다.
시간 선택 뒤 배송 주소나 요청사항으로 이동하는 대상도 연결하지 않았다.
배송 주소·받는 분 입력은 하나의 긴 폼 안에 있어 작성 후 다음 항목으로 이동하는 조작이 없었다.

## 적용

- 날짜 선택 → 해당 폼의 시간 목록으로 이동.
- 픽업 시간 선택 → 요청사항으로 이동.
- 배송 시간 선택 → 배송 주소·받는 분 입력으로 이동.
- 날짜를 바꾸면 기존 시간 선택을 초기화한다.
- 배송지·받는 분·연락처를 입력하고 ‘배송정보 입력했어요’를 누르면 요청사항으로 이동한다.
- 주소를 입력하는 동안에는 자동 이동하지 않는다.
- 요청사항 이후 주문금액/안내·동의항목으로 이동하는 버튼을 추가했다.
- 각 주문 폼과 시간 선택 영역은 고유 ID로 연결하여 다른 상품이나 숨겨둔 경로로 이동하지 않는다.
- 픽업/배송 변경 시 입력값은 보존하며, 배송만 주소 필드를 표시한다.
- 고정 헤더 아래 96px 스크롤 여백을 공통 적용하고, 중첩 입력 그룹의 필드 간격을 유지했다.
- 동작 감소 설정에서는 부드러운 이동 대신 즉시 이동한다.

## 범위

꽃다발·꽃바구니·서양난·JUST ROSE: 공통 PickupOrder 경로.
관엽화분·계절 동양난: PlantOrder 경로.
호텔 프로포즈: 진행 안내 → 예약정보, 날짜 → 체크인 시간, 체크인 → 요청사항 연결.
축하화환: 날짜 → 시간 → 장소 확인 안내 연결. 시간 목록에도 위로 떠오르는 애니메이션을 적용하지 않는다.
근조화환: 수령 시간 입력이 없는 기존 펼침형 단계 이동을 유지한다.
클래스: 단일 문의 폼과 현재 화면 안 미리보기 흐름을 유지한다.
다중 옵션·약관 체크·글자 입력에는 무조건 다음 칸으로 이동시키지 않는다.

## 검증

기존 통합 UI 검사에 꽃/식물의 실제 scrollIntoView 목적지 검사를 추가했다.
날짜 → 시간, 시간 → 배송정보/요청사항, 배송정보 → 요청사항, 요청사항 → 안내/동의 이동과 입력 중 스크롤이 발생하지 않는 것을 검사한다.
픽업↔배송 값 보존, 날짜 변경 시 시간 초기화, 숨긴 경로 제외와 감소 동작 검사를 유지한다.
실제 iOS/Android의 가상 키보드와 화면상 움직임은 실기기 최종 검수가 필요하다.

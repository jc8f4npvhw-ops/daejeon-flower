# 배송완료 카카오 연결 · 2026-10-21

## 현재 코드에 구현된 범위
- 기존 주문자 전화번호로 배송완료 알림톡을 발송한다. 수령인 번호를 발송 대상으로 사용하지 않는다.
- 고객이 배송 알림 선택 항목을 체크한 배송 주문만 대상이다. 픽업·미동의·미결제 주문은 제외한다.
- 채널 친구 여부는 현재 고객의 체크 확인이다. 카카오 API로 실제 친구 상태를 검증한 것이 아니다. 로그인·회원/전화번호 검증·친구 상태 자동 확인은 후속 구현 범위다.
- 사진 업로드 후 배송완료 상태 변경과 발송 대기열 등록은 같은 D1 batch에서 처리한다.
- 동일 주문의 재완료·동시 처리로 중복 이벤트를 생성하지 않는다. 발송 전 취소된 이벤트는 다시 완료할 때 재활성화할 수 있다.
- 서버가 SOLAPI API에 직접 HMAC 요청한다. 별도 자동화 프로그램·SOLAPI SDK 설치는 필요 없다.
- 기본형 승인 템플릿으로 고객 전용 사진 페이지 링크를 보낸다. 카카오 말풍선에 주문마다 다른 사진을 직접 첨부하는 방식이 아니다.
- private R2 원본과 공개 제작사진 갤러리는 별개다. 고객 링크는 해당 주문의 배송완료 사진만 접근하며 고인·주소·전화번호·리본문구를 API 응답에 넣지 않는다.
- 고객 링크의 토큰은 URL fragment로 전달한 뒤 HttpOnly cookie로 교환하며 주소창에서 제거한다. 링크 유효기간 90일, cookie 7일. 링크를 전달받은 사람은 사진 접근이 가능하므로 고객에게 공유하지 않도록 안내한다.
- 완료를 제작중으로 되돌리면 고객 사진 접근을 차단한다.
- 접수됨(ACCEPTED)과 전달완료(SENT)는 별도다. 5분 cron으로 SOLAPI 결과를 조회한다.
- 통신 응답이 불명확하면 UNKNOWN으로 두고 자동/관리자 재발송을 막는다. SOLAPI 발송 내역을 확인해야 한다.
- SMS 대체발송 사용 안 함.
- 관리자 '배송 카카오 알림'에서 설정 상태·전화번호 끝자리·발송 상태·실패 재시도를 확인한다. 비밀값 입력란은 없다.

## 기존 D1 준비
사용자가 제공한 31개 업무 테이블 구조는 기존 기본 SQL과 일치했다. Cloudflare 내부 _cf_KV는 제외했다.
`scripts/prepare-current-d1-20261021.sql`은 기존 구조 위에 필요한 11개 테이블(기존 관리자 추가분 9개 + 배송 알림 추가분 2개)과 관련 인덱스를 추가한다.
CREATE IF NOT EXISTS만 포함하며 기존 고객·주문·상품·설정 값을 수정하지 않는다. 코드에서 준비하고 로컬 검증했을 뿐 원격 적용 전이다.
이 파일은 현재 확인한 기존 DB를 위한 준비 파일이다. tests/existing-D1-FINAL.sql이나 seed SQL을 원격에 재실행하지 않는다. 원격 migration 이력이 확인되지 않았으므로 `npm run migrate` 전체 실행도 보류한다.
현재 UI의 품종·가격 초기 데이터 일치 여부는 테이블 구조 조회만으로 확정하지 않았다. 신규 도입 시 0005 품종 데이터 적용 여부를 별도로 검토한다.

## Cloudflare 서버 설정: 이후 사용자와 단계별 진행
1. 최신 소스를 GitHub에 반영하고 단일 Worker daejeon-flower를 배포한다. 기존 D1과 R2 binding을 유지한다.
2. 기존 DB 구조 추가 SQL을 적용하고 추가 테이블 확인. 주문 접수는 아직 열지 않는다.
3. 실제 HTTPS 사이트 주소를 PUBLIC_ORIGIN에 등록. 처음에는 운영 DNS를 바꾸지 않고 배포 확인 주소를 사용할 수 있다.
4. SOLAPI_API_KEY와 SOLAPI_API_SECRET은 Cloudflare Secrets에 직접 입력. 채팅/브라우저 코드/GitHub에 저장하지 않는다.
5. SESSION_SECRET을 등록. 이 값 변경 시 관리자 세션 및 기존 고객 사진 링크가 무효화되므로 운영 중 임의 교체하지 않는다.
6. KAKAO_TEST_PHONE에 사용자의 테스트 휴대폰 번호를 서버 비밀값으로 등록.
7. KAKAO_SENDING_ENABLED=true, KAKAO_LIVE_SEND_ENABLED=false. 이 상태에서는 지정 번호에만 요청을 보내며 다른 주문은 설정 대기로 보류한다.
8. 테스트 결제/주문 상태·사진을 준비한 뒤 해당 번호로 배송완료 알림 및 사진 페이지를 확인. 현재 실제 테스트 주문/발송은 수행하지 않았다.
9. SOLAPI 잔액/한도, 정보처리 위탁 고지, 환불·판매 정책, 친구 확인 방식 등 실제 오픈 조건 점검 후 KAKAO_LIVE_SEND_ENABLED=true로 전환한다. 보류된 유효 발송 건도 처리되므로 전환 전 대기열 확인.

## 미완료 범위
실제 Cloudflare 배포·원격 D1 추가·R2 이전·Secret 등록·실카카오 수신 테스트·고객 정식 오픈은 하지 않았다.
카카오 회원 로그인/전체 생년월일 저장, 기념일 D-3 안내, 리뷰 후 쿠폰 자동 발급은 이 배송완료 구현에 포함되지 않는다.
기존 관리자 전체가 최종 확정됐다는 의미가 아니다. 이번 코드는 배송완료 연결을 위한 단계별 작업본이다.

이 파일 하나만 사용하세요. 11월 10일 앞서 받은 환불·UI ZIP은 따로 적용하지 않아도 됩니다.

1. 운영 사이트에는 먼저 환불정책과 화면 수정만 배포
ZIP을 풀고 daejeon-flower-final 안의 내용을 기존 저장소의 같은 폴더에 덮어씁니다.
GitHub Desktop에서 cloudflare-latest 브랜치에 Commit → Push origin.
Cloudflare 배포가 성공하면 https://대전꽃백화점.com/refund 가 열리는지 확인합니다.
이 공개 주소가 PG 심사에 제출할 환불정책 URL입니다.
wrangler.jsonc는 패키지에서 제외했습니다. 운영 PAYMENTS_ENABLED와 관리자 결제 설정을 켜지 마세요.

2. 토스페이먼츠 테스트 연결
기존 홈페이지는 토스페이먼츠 SDK v2 주문서형 결제를 사용합니다.
토스페이먼츠 개발자센터 → API 키 → 주문서형·결제창형 연동 키에서 테스트 키 한 쌍을 사용하세요.
테스트는 운영 D1/R2를 공유하지 않는 별도 Worker 및 별도 DB/버킷에서 진행합니다.
해당 테스트 Worker 런타임 Secrets에 TOSS_CLIENT_KEY와 TOSS_SECRET_KEY를 등록합니다.
테스트 Worker에서 PAYMENTS_ENABLED=true로 두고, 테스트 DB에서 운영 정책 확인 및 결제 사용을 켭니다.
테스트 결제 승인·취소·실패 후 재시도, 승인 응답 재진입 시 중복 승인 없음, 관리자 주문 반영을 확인합니다.
웹훅을 등록할 때는 해당 환경의 https://호스트/api/payments/webhook 에 PAYMENT_STATUS_CHANGED를 연결합니다.
API 키, 특히 시크릿 키는 채팅·스크린샷·GitHub에 보내지 마세요.

3. 운영 실결제
토스 심사 승인과 테스트가 끝난 뒤 승인받은 상점의 라이브 키로 운영 Worker를 설정합니다.
운영 전환 전에는 운영 DB의 실제 약관·개인정보·환불 안내와 결제 수단을 확인합니다.
환불 페이지의 차감표는 별도 동의를 받은 적용 대상 주문의 안내입니다.
관리자 취소는 기존 PG 취소 흐름을 사용하며, 차감표를 자동 적용하지 않습니다.
토스가 아닌 PG로 신청했다면 이 키 이름으로 등록하지 말고 PG 이름부터 확인합니다.
